---
name: Booking calendar mobile sizing
description: Responsive sizing rules for the client booking calendar inside its mobile sheet.
---

When customizing DayPicker class names for the booking sheet, replacement values must include the complete layout primitives for months, weeks, weekdays, days, navigation, caption, and table—not only incremental utility classes. Keep the grid as a consistent table layout: fixed table columns with normal table rows and explicit cell-height rows. Size booking day cells from the narrowest viewport upward, then increase only at breakpoints that have been browser-verified. On small phone sheets, the outer sheet body must be the only scroll boundary; the booking card must grow naturally inside it and must not introduce a second scroll area. Apply `touch-action: pan-y` to that booking-only sheet body, never globally.

**Why:** DayPicker treats supplied class names as replacements; a partial override can remove the width and flex rules that distribute seven days, collapsing date targets even when the outer calendar appears contained. Mixing a block table and row group with flex table rows can underreport the calendar's height when a month has six weeks, causing later booking content to start under the final rows. Nested scroll containers can make iOS route a touch gesture to an element without a usable scroll range, while a sheet-specific `pan-y` keeps vertical booking navigation reliable without interfering with horizontal carousels elsewhere. Forcing the card to a sheet's exact height on a very short viewport can still clip its correct internal layout before its own scroll body receives space.

**How to apply:** Validate actual button dimensions alongside overflow and stacking at 320px, 375px, and 414px whenever booking-calendar layout classes change. Include a six-week month at 375px and verify the final two rows, legend, and slots section have separate bounding boxes. Also make a real touch swipe from a calendar cell at 393×852; verify that one mobile drawer scrollTop changes, the document stays fixed, and the afternoon/evening slots can be reached.
