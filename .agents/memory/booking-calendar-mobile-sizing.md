---
name: Booking calendar mobile sizing
description: Responsive sizing rules for the client booking calendar inside its mobile sheet.
---

When customizing DayPicker class names for the booking sheet, replacement values must include the complete layout primitives for months, weeks, weekdays, days, navigation, caption, table, and row group—not only incremental utility classes. The booking table and row group must use block auto-height layout when week rows use flex. Size booking day cells from the narrowest viewport upward, then increase only at breakpoints that have been browser-verified. On small phone sheets, the outer sheet body must be the scroll boundary; the card must be allowed to grow with its content. The card and its scrollable body must also opt into `min-height: 0` so content stays above its action footer.

**Why:** DayPicker treats supplied class names as replacements; a partial override can remove the width and flex rules that distribute seven days, collapsing date targets even when the outer calendar appears contained. A table that contains flex week rows can underreport its height when a month has six weeks, causing later booking content to start under the final rows. Flex children also default to an intrinsic minimum height, which can let the date-and-slots section paint under a sibling footer on short mobile sheets. Forcing the card to a sheet's exact height on a very short viewport can still clip its correct internal layout before its own scroll body receives space.

**How to apply:** Validate actual button dimensions alongside overflow and stacking at 320px, 375px, and 414px whenever booking-calendar layout classes change. Include a six-week month at 375px and verify the final two rows, legend, and slots section have separate bounding boxes. Also test short viewports and verify the date-step body scrolls independently until all slots are visible above the footer.
