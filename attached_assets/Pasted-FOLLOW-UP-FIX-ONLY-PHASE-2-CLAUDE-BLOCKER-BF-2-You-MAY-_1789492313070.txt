==================================================
ROOT CAUSE — BF-2
==================================================

File:

scripts/src/production-startup-ddl-inventory.ts

The BF-1 correction added CallExpression and NewExpression handling inside
scanTopLevelModule().

Those branches correctly resolve/scan indirect executable calls.

BUT:

they now end with unconditional:

return;

That prevents the existing AST walker from descending into the
CallExpression/NewExpression children.

Before the BF-1 correction, unresolved/wrapper calls fell through to:

ts.forEachChild(node, visit)

and therefore nested SQL sinks inside their arguments were detected.

The BF-1 fix accidentally removed that coverage.

Claude verified differential regressions such as:

wrapUnknown(
  client.query(`CREATE TABLE ...`)
)

Promise.all([
  client.query(`CREATE TABLE ...`)
])

Promise.all([
  db.execute(`CREATE INDEX ...`),
  db.execute(...)
])

new UnknownThing(
  client.query(`CREATE TABLE ...`)
)

await unknownWrap(
  client.query(`CREATE TABLE ...`)
)

register({
  init: client.query(`CREATE TABLE ...`)
})

These were:

OLD analyzer: DETECT
CURRENT analyzer: MISS

This is a regression introduced by the BF-1 correction.
