BLOCKER-1 — 16 startup data-mutating statements are absent from both the 1,435 mappings and the 94 additional operations

HIGH-1 — The validator accepts fabricated RETIRED_HISTORICAL and FUTURE_MIGRATION_REQUIRED with zero evidence

scripts/src/startup-migration-crosswalk.ts:778-788

Only CANONICAL_BASELINE is guarded. I re-validated a crosswalk with all 1,435 mappings relabelled RETIRED_HISTORICAL — accepted. The test at startup-migration-crosswalk.test.ts:43 is named "fails closed instead of inventing canonical, future, or retired equivalence" but only inspects builder output; it never asserts that the validator rejects those two statuses. A hand-edited or downstream-produced crosswalk can claim every startup operation is retired history and pass the gate.

HIGH-2 — The CANONICAL_BASELINE guard is self-asserted and trivially forged

scripts/src/startup-migration-crosswalk.ts:781-786

The guard checks fields the document supplies about itself (semanticsVerified, evidenceType, lineReferences.length). It never re-derives evidence from migration.sql. Setting semanticsVerified: true plus one fabricated line reference on all 1,435 mappings was accepted. lineReferences are never checked for existence or for actually containing the object name.

HIGH-3 — No pinned expectation for the 94; the additional-operation check is self-referential

scripts/src/startup-migration-crosswalk.ts:818-822, startup-migration-crosswalk.test.ts:75

validateStartupMigrationCrosswalk compares crosswalk.additionalOperations against the module-level ADDITIONAL_STARTUP_OPERATIONS, which is recomputed at import from live source (:622). The test asserts crosswalk.additionalOperations.length === ADDITIONAL_STARTUP_OPERATIONS.length — tautologically true. The number 94 appears nowhere in the code or the tests. If a source edit causes discovery to find 60, every test still passes. Worse, the 19 curated entries' content is never verified against source — validation only checks that the module file is readable (:814), so their summaries, line ranges and rollback claims can silently drift from the code they describe.

MEDIUM-1 — Curated blanket line ranges can silently swallow future operations

scripts/src/startup-migration-crosswalk.ts:546-556, 585-586

education-bundle/transaction-and-advisory-lock declares education-bundle-purchase-schema.ts:4-85 and referral/transaction-and-advisory-lock declares referral-schema.ts:14-54 — ranges spanning the entire owner function. discoveredAdditionalOperations suppresses any discovered operation whose line falls in any curated range (.some(...)). Today the more specific entries win by array order and nothing extra is lost (I verified all 9 suppressed literals are genuinely described by their suppressing entry). But any mutation added inside those spans in future is suppressed with no signal.

MEDIUM-2 — existingDataEffect is derived from a kind-name prefix and mislabels the riskiest operations

scripts/src/startup-migration-crosswalk.ts:202-207

The classifier returns fresh-and-existing-idempotent for anything not prefixed alter-/drop-/validate-. Result in the generated artifact:

- 85 add-constraint → fresh-and-existing-idempotent
- 551 create-index, of which 101 are CREATE UNIQUE INDEX → fresh-and-existing-idempotent
- 186 create-table, 29 create-trigger → same

A CREATE UNIQUE INDEX against existing production rows is precisely the non-idempotent case — it is the reason shipping/duplicate-row-cleanup exists as a curated entry in this same file. Design point 5B-2 §2 asks whether each operation is required for existing data or only fresh init; a prefix test cannot answer that, and the field currently understates risk on 858 of 1,435 mappings.

MEDIUM-3 — Destructive ALTER TYPE … RENAME VALUE semantics are erased from the mapping summary

business-growth-schema.ts:1612 executes ALTER TYPE ${s}.user_role RENAME VALUE 'EDUCATION_CENTER_OWNER' TO 'EDUKATIVNI_CENTAR'. The crosswalk surfaces it as summary ALTER TYPE ${s}.user_role — the rename is gone. The root cause is the inventory's alter-type pattern (production-startup-ddl-inventory.ts:341), whose optional tail matches only ADD VALUE, but the crosswalk republishes the truncated text as the authoritative record a reviewer will act on.

MEDIUM-4 — Occurrence records carry no position, so 1,459 occurrences collapse to 26 distinguishable keys

scripts/src/startup-migration-crosswalk.ts:242-251

occurrence() records sourcePath: operation.module (file, no line) plus callSite/phase/executionPath, which are near-constant per owner. Measured distinct occurrence keys: ensureBusinessGrowthSchema 26 for 1,377 records; ensureMediaSchema 1 for 26. For 19 of the 20 duplicated fingerprints the two occurrence entries are byte-identical. The occurrence array preserves the count but cannot tell a reviewer where any of the 1,459 operations is, nor in what order they execute — which is what 5B-2 §3 ("execution ordering") asks for.

MEDIUM-5 — Statically-resolvable identities are degraded to <dynamic>, and ${s} is silently asserted to be public

scripts/src/startup-migration-crosswalk.ts:118, :131-198

- ALTER TABLE ${table("salons")} … yields {schema:"<dynamic>", name:"${table", dynamicExpression:"${table"} — the regex [^\s(;]+ truncates at (, discarding the statically known table name. Affects at least salons, beauty_job_listings, products, courses.
- DROP INDEX %I.%I' yields name: "%I.%I'" — normalizedIdentifier strips " and trailing [,;()] but not '.
- Line 118 rewrites ${s}. / ${schema}. / ${quoted}. to public., so 1,319 of 1,435 mappings assert schema: "public" for statements whose schema is a runtime parameter (ensureReferralSchema(schemaName = "public") is called with tenant schemas in tests).

All of these fail closed (UNRESOLVED, no line references), so nothing unsafe is claimed — but the identity fields are less accurate than they read.

LOW-1 — canonicalEvidence scans all 19,417 canonical lines per mapping

scripts/src/startup-migration-crosswalk.ts:230-236. The matches.length < 5 cap is inside the forEach callback, so there is no early exit: ~27.9 M line comparisons with line.toLowerCase() recomputed 1,435× per line. Not a problem at current scale (3.7 s total); pre-lowercasing canonicalLines once would remove most of it.

LOW-2 — Substring matching inflates candidate-name-match

scripts/src/startup-migration-crosswalk.ts:232 uses includes(token), so a short object name matches unrelated identifiers that contain it. 1,386 of 1,435 mappings report candidate-name-match. Harmless because semanticsVerified stays false and resolutionReason says so explicitly, but the signal is weak.

LOW-3 — validateStartupMigrationCrosswalk alone does not re-read migration.sql

scripts/src/startup-migration-crosswalk.ts:727-729 compares against the hardcoded constant. Only buildStartupMigrationCrosswalk (:632) hashes the file. Calling the exported validator standalone on an already-built document would not notice canonical-migration drift.

LOW-4 — Pre-existing, not introduced here

scripts/package.json contains duplicate keys (test:internal-request-control-outputs, test:admin-navigation-regression, test:admin-bounded-pagination) — present before ea35d882, listed only so it is not mistaken for new damage. startup-migration-crosswalk.ts has no trailing newline at EOF.

Assessment

The scaffolding is genuinely sound: counts reconcile against the real baseline, the canonical checksum is enforced at build, output is byte-deterministic and cwd-independent, memory and runtime are unremarkable, nothing outside the three intended files moved, and the builder never invents equivalence. Fourteen of the fifteen structural tamper attempts I ran against mapping identity were correctly rejected.

But two claims the phase rests on do not hold. The 94 additional operations are not complete — sixteen executed startup data mutations, including a mass rewrite of user roles and the cancellation of financial payment obligations, are represented nowhere in the artifact, and the validator cannot detect this because it compares discovery output to itself. And "every mapping is UNRESOLVED" is a property of the builder that the validator does not enforce: relabelling all 1,435 mappings as retired history, or forging canonical equivalence, both pass.

A crosswalk whose purpose is to be the evidence base for removing startup DDL cannot ship while it omits startup writes to users.role and education_payment_obligations.status.

REJECT PHASE 5B-3 — FIXES REQUIRED

Blocking: BLOCKER-1, HIGH-1, HIGH-2, HIGH-3. MEDIUM-1 through MEDIUM-5 should be addressed in the same pass since they affect the same records. This verdict concerns the crosswalk infrastructure only; it approves no mapping, no forward migration, no startup-DDL removal and no production change.
