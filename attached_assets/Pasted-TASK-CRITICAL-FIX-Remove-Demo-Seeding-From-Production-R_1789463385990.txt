Context:

Two independent audits have confirmed a CRITICAL production data-safety issue.

Current main allows normal HTTP request handling to reach:

ensureDemoData()
→ seed()

When any user already exists, seed() enters an existing-users branch BEFORE
the production demo-seed opt-in is checked.

Confirmed consequences include:

- demo services can be assigned to real salons
- confirmed demo appointments can be created using real salons,
  employees, services and CUSTOMER accounts
- backfillSalonCustomers can then associate those customers and their
  contact information with those salons
- real salon settings can be modified
- taxonomy/catalog records can be modified
- qualifying product visibility/pricing can be modified
- process-local seedPromise does not protect across Autoscale instances

This task must remove that architecture safely.
