REQUIRED FIX 2 — P1-2
ROBUST BASE-SHA ANCESTRY UNDER SHALLOW CHECKOUT
==================================================

Independent review reproduced a real false failure.

Current behavior:

checkout fetch-depth: 2

then:

git fetch --no-tags --depth=1 origin "$PR_BASE_SHA"

then validator performs:

git merge-base --is-ancestor "$PR_BASE_SHA" HEAD

Problem:

if the recorded trusted base SHA is older than the current merge
commit's first parent, the shallow graft can sever the ancestry chain.

The base object exists but Git cannot prove ancestry.

This causes legitimate PRs/job re-runs to fail.

Fix this WITHOUT weakening the trust model.

Critical invariants:

- exact trusted base SHA remains authoritative
- NEVER substitute branch tip for the recorded SHA
- NEVER fall back to a mutable branch name as the comparison identity
- ancestry proof remains mandatory where Gate B requires it
- if ancestry cannot be proven, fail closed

Use a bounded/deepening strategy.

Possible safe shape:

1. fetch exact trusted base SHA
2. attempt ancestry proof
3. if shallow history prevents proof, deepen history in controlled steps
4. retry ancestry proof
5. optionally unshallow only as final bounded fallback if justified
6. still compare against the SAME exact trusted base SHA

Do not change reference identity during retry.

Do not simply remove merge-base --is-ancestor.

Do not accept "object exists" as sufficient.
