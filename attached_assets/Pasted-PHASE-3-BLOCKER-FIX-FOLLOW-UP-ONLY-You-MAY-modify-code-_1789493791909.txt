2. BLOCKER P3-BL-1
SHIPPING + WEB PUSH TRANSACTION LEAK
==================================================

Files:

artifacts/api-server/src/lib/shipping-config.ts
artifacts/api-server/src/lib/web-push-schema.ts

Current Phase 3 ordering became:

BEGIN
→ SET LOCAL timeout
→ pg_advisory_lock
→ DDL
→ COMMIT

But rollback currently exists only in an inner try around DDL/commit.

Therefore if:

setLocalStartupDdlTimeouts()

or:

pg_advisory_lock(...)

throws after BEGIN succeeded, no ROLLBACK executes.

The client can then be released into the node-postgres pool with an open or
aborted transaction.

This is NEWLY INTRODUCED by Phase 3.

Required minimal correction:

Ensure the OUTER transaction scope catches every error after BEGIN and
attempts:

await client.query("rollback").catch(() => {});

before rethrowing the ORIGINAL error.

Use the same safe structural pattern already used by:

- media
- referral
- booking-command
- education-bundle

Requirements:

- rollback covers timeout setup failure;
- rollback covers advisory-lock acquisition failure;
- rollback covers DDL failure;
- rollback covers COMMIT failure where rollback is still applicable;
- original error remains primary;
- unlock only attempted if locked === true;
- client.release() always occurs;
- no pooled client is returned in an open/aborted transaction.

Do not change SQL DDL.
